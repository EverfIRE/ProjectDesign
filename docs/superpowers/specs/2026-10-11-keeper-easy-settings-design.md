# Keeper 可点击设置面板与 Easy 模式

状态：设计提案，等待用户审阅；尚未修改产品代码。

## 已确认的需求

- 提供可点击的插件设置面板，不能只交付配置文件或命令。
- Easy 模式跳过 Keeper 自己的人工确认，保留全部自动校验。
- Easy 模式取消单文件大小上限。
- 用户可配置一次更新全部知识文件的合计大小上限；该上限在两种模式下均生效。
- 使用新的版本号提交并发布，拟定功能版本为 1.1.0。

## 入口方案

推荐：通过 Keeper 的“打开设置”工具显示 MCP Apps 面板。用户可在聊天中要求“打开 Keeper 设置”，随后直接点击开关、填写数值并保存。此方案复用插件已有 MCP 服务，不新增常驻本地 HTTP 服务。

备选：独立本地浏览器设置页，同样可点击，但需要管理本地端口、页面访问和服务生命周期。只有宿主无法渲染 MCP Apps 时才考虑采用，不能以命令行代替用户要求的面板验收。

不采用：在插件清单中编造自定义原生设置页字段。当前查到的官方扩展方式是 MCP 工具返回 UI 资源，不是向 Codex 的插件管理页直接注入控件。实际安装后的宿主显示必须单独验证。

参考：

- [OpenAI：为 MCP 服务添加 UI](https://developers.openai.com/plugins/build/chatgpt-ui)：UI 资源、交互桥接和服务端持久状态。
- [OpenAI：插件本地配置](https://developers.openai.com/plugins/guides/submit-claude-plugin#replace-claude-userconfig)：本地设置可使用配置文件，不能依赖 Claude 的安装配置提示。

## 面板行为

面板使用中文标签，包含：

1. **Easy 模式**开关，默认关闭。
2. **单次更新合计上限**数字输入框，单位 MiB，默认 8。建议首版支持 1–64 MiB 的整数；这是可见的合计上限范围，不是另设单文件上限。
3. 只读说明：普通模式“单文件上限 2 MiB”；Easy 模式“无独立单文件上限，受本次合计上限约束”。
4. **保存设置**、**恢复默认值**按钮；恢复默认值先填入表单，点击保存后才生效。
5. 当前生效值、未保存状态、保存中、保存成功和错误提示。保存失败时保留用户输入，不显示虚假的成功状态。

设置作用域为本机当前用户的 Keeper 安装，跨项目、跨任务保留，升级插件时不覆盖。该作用域在面板上明确显示。保存后的设置供下一次操作使用，无需重启；正在执行的操作使用开始时取得的配置快照。

## 模式与授权

| 行为 | 普通模式 | Easy 模式 |
| --- | --- | --- |
| 自动内容、证据及结构校验 | 保留 | 保留 |
| 路径、签名、过期、冲突及恢复保护 | 保留 | 保留 |
| Keeper 人工确认、输入摘要码 | 需要 | 跳过 |
| 单个待写入知识文件上限 | 2 MiB | 无独立上限 |
| 一次更新全部待写入知识文件合计 | 使用配置值 | 使用配置值 |

Easy 模式是用户预先保存的插件策略，不允许某次 `apply_update` 调用临时传参启用。设置保存与知识写入分开；打开面板或展示预览不修改模式。面板点击保存才更改持久设置，模型不能因任务失败自行开启 Easy 模式。

自动校验成功后，Easy 模式沿用已有一次性授权和事务路径；仅替换人工确认这一环节。校验失败仍拒绝写入。插件不能关闭或绕过宿主自己的工具权限提示。

授权记录应区分 `easy-policy` 和 `human-form`，保留所用配置修订号。Easy 策略授权不能被记录成用户逐条手动确认，也不能将自动校验失败的内容标为已通过。

工具返回当前有效模式，技能说明据此选择流程：Easy 模式下不再另行请求聊天确认，也不再要求语义决策的人工作答；自动语义检查及任务范围约束继续执行。普通模式保持原有确认流程。

## 大小计量与完整流程

合计按本次实际待写入的最终文件内容计算 UTF-8 字节数：

- 每个目标文件计算一次。
- managed block 更新计算合并后的完整目标文件，不能只计算传入的块。
- 删除项不增加新的写入内容字节。
- 参数 JSON、摘要、签名、快照等内部元数据不计入用户设置的知识文件合计值。

Easy 模式的大小验收例子：合计上限 8 MiB 时，单个 3 MiB 或 6 MiB 文件可通过大小检查；9 MiB 单文件或合计 9 MiB 的多文件更新被合计限制拒绝。普通模式仍拒绝超过 2 MiB 的单文件，即便合计未超限。

输入、预览、候选包校验、持久化、再次加载、正式写入和恢复必须共用同一份运行策略，不能在后续流程被残留的 2 MiB 常量拦截。更新合计上限时，相关请求和缓存预算根据有界的内容及序列化开销计算。源码扫描和其他工具预算不因 Easy 模式而全部解除。

旧文件读取与新内容写入分别计量。关闭 Easy 模式之后，不能仅因为原文件由 Easy 模式创建且超过 2 MiB，就无法读取它以执行合法的缩小或删除操作。读取、快照和恢复仍须有独立且明确的资源预算。

当前预览全文受 768 KiB 差异和 1 MiB 工具返回大小限制。新版本保留单次返回的有界性，将过大的差异存入已认证的变更集，并提供分页读取接口。预览首屏返回完整统计、是否存在后续页及分页入口；不得把截断的差异标为完整。普通模式需提供完整审阅路径，Easy 模式不要求用户逐页确认。

## 配置、并发与持久化

- 配置存放在插件用户数据目录，使用带版本及修订号的 JSON；不从任意项目文件读取 Easy 开关。
- 保存采用校验、锁和原子替换；两个面板同时保存时检查修订号，拒绝静默覆盖。
- UI 保存接口仅通过明确的用户设置流程调用；不得将“模型隐藏工具”视为服务端授权机制。
- 缺少配置时使用普通模式及默认大小；损坏或非法配置显式报错，不自动开启 Easy。
- 预览绑定配置修订号。预览之后更改设置，旧预览在应用前要求重新生成，避免静默套用另一种确认模式或大小预算。
- 已经进入写入阶段的事务继续用已冻结的策略完成或回滚；保存设置不改变进行中的事务。
- 新变更集格式必须明确标记策略和分页差异绑定。旧格式预览升级后提示重新生成，不悄悄转换成 Easy 授权。

## 代码与发布范围

新增设置存储、设置面板资源和设置/差异分页工具；修改服务组装、MCP 注册、事务、限制解析和变更集持久化，使策略贯穿全部流程。同步工具清单、安装冒烟契约、用户技能和发布包契约。

UI 资源随插件打包，在本地运行，不引入远程账号、遥测或外部配置服务。保留原有九个工具的名称与用途，新功能通过新增工具和兼容的返回字段提供。

完成后发布 1.1.0，更新源码与生成发布目录、安装校验脚本、发布说明和版本标签。新用户默认仍为普通模式；本次需求本身不等于替用户开启全局 Easy 模式。

## 验收

1. 在真实可交互面板中打开、切换、输入、保存、刷新和恢复默认值；验证键盘操作和错误提示。
2. 验证设置跨进程、跨任务及升级持久；多个面板保存冲突可见。
3. 普通模式仍弹确认且错误摘要码不写入；Easy 模式不触发 Keeper 的人工确认请求。
4. 两种模式均拒绝篡改、过期、路径越界、源文件变化及无效候选内容。
5. Easy 模式下大于 2 MiB 的单文件通过真实预览、完整分页、缓存重载及写入；合计恰好等于上限通过，超过一个 UTF-8 字节拒绝。
6. 覆盖中文、多文件、managed block、删除、降低上限、预览后切换模式、并发保存和回滚场景。
7. 类型检查、相关回归、完整测试、独立运行冒烟、打包及源码/发布一致性通过；测试期间不改动被测试的仓库文件。
8. 更新插件后实际验证宿主面板。源码测试通过不能替代真实界面验收；若宿主不支持，明确报告并采用可点击的本地页面方案。
